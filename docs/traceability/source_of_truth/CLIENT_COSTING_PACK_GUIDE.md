# Client Costing Pack Guide

## Recommendation
Do **not** share the internal planner app directly with the client.

The planner app is useful for:
- internal scenario testing
- rate-card discussions
- third-party what-if analysis
- refresh from workbook

But it is too technical for client-facing communication because it exposes:
- internal rate mechanics
- editable scenario controls
- operational assumptions that may confuse budget conversations
- retained/internal enterprise reference costs

## What To Share With The Client

Share a clean 3-part costing pack instead:

### 1. Executive Cost Summary
Keep this to one page.

Show:
- total project cost
- cost by release
- monthly cost curve
- post-launch support estimate

Do not show:
- every internal control
- optional toggles
- workbook mechanics

### 2. Basis Of Estimate
This is where you explain the numbers in plain language.

Include:
- delivery duration
- number of releases
- staffing basis
- third-party services included
- contingency approach
- assumptions
- exclusions

### 3. Optional / Decision-Dependent Costs
Keep these separate from the main budget.

Examples:
- route provider
- payment gateway selection
- OCR
- travel beyond current assumption

This avoids the client reading optional items as committed base cost.

## Best Client-Facing Views

The cleanest client views are:
- release summary
- monthly budget summary
- third-party recurring cost summary
- post-launch support summary

## Internal vs Client Boundary

### Internal Only
- planner app
- detailed rate-card tuning
- editable scenario controls
- role-by-role live recalculation
- retained enterprise references

### Client Safe
- approved budget baseline
- release-by-release cost summary
- monthly planned spend
- support/hypercare estimate
- assumptions and exclusions

## Suggested Delivery Format

Best order:
1. client-facing Excel summary workbook
2. matching PDF export for review/sign-off
3. optional presentation slide with release budget chart
